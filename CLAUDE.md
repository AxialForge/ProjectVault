# ProjectVault — project guide for Claude Code

Personal CAD/maker project library. Electron desktop app, Windows installer, one
user. It owns a local library folder (files are copied in, catalogued in SQLite,
versioned, previewed) and mirrors it one-way to a NAS. See README.md for the
feature description; this file is about how the code is put together.

## Non-negotiables (don't regress these)

- **No native Node addons.** SQLite is sql.js (WASM), zip reading is hand-rolled,
  image resizing is Electron's nativeImage, 3D/PDF rendering happens in the
  renderer. This machine cannot build native modules (see the global memory on
  the Node 24 ClangCL trap) and the installer must work without them.
- **The library folder is self-contained.** Everything the app knows lives in
  `<Library>/projectvault.db` and `<Library>/.projectvault/`. Copying the folder is a
  complete backup. Files are copied in, never linked or referenced in place.
- **Original filenames stay at the top of the project folder.** SolidWorks and
  Inventor assemblies resolve parts by filename in the same directory.
- **Nothing is ever hard-deleted, and every deletion has a reason.** Local delete
  = move to `.projectvault/trash/`. NAS side = move to `_Deleted/<stamp>/` and
  append to `_Deleted/deletions.log`. The NAS is never pruned of files the app
  doesn't know about.
- **Extracted data is read-only.** The user's own notes/fields are separate.
- **Works offline.** The NAS is only touched by an explicit backup (or the
  opt-in backup-on-quit).
- **No paid services, no code signing.**

## Commands

```bash
npm install                 # then: node node_modules/electron/install.js if the binary is missing
npm run vendor              # refresh src/renderer/vendor from node_modules (three, pdf.js)
npm run icon                # assets/icon.svg -> icon.png + icon.ico
npm run dev                 # from-source run; userData is "<app>-dev" so it coexists with the installed app
npm test                    # node --test; pure-Node modules only
npx electron scripts/smoke.js <lib> <paths...>   # main-process import + extraction check
npm run dist                # dist/projectvault-<version>-setup.exe
```

Node 22+ (24 in use). Electron's bundled Node provides `zlib.zstdDecompressSync`,
which Fusion `.f3d` archives need; the CI runner's Node 22 only runs tests.

## Architecture

Main process = all file system and catalogue work. Renderer = UI plus the three
preview jobs only a browser can do (WebGL mesh render, pdf.js, video frame).
They talk through the `api` object in `preload.js`; every IPC channel is listed
there.

```
src/main/
  main.js          window, IPC handlers, the lib:// protocol (serves library files to the page, CORS-enabled), backup-on-quit
  preload.js       the api surface exposed to the renderer
  settings.js      settings.json in userData: libraryPath, nasPath, theme, backupOnQuit
  db.js            sql.js wrapper; schema; debounced flush to projectvault.db
  library.js       projects/items/versions/fields/history/search/deletions; folders (real records, moves rewrite paths); disk layout rules
  backup.js        one-way mirror + deletion processing (pure Node, unit-tested)
  updater.js       template silent updater (unchanged)
  extract/
    index.js       THE EXTENSION POINT: extension -> kind, extension -> handler
    ole.js         SolidWorks/Inventor: OLE streams, thumbnail scan, property sets
    containers.js  zip-based: f3d, FCStd, 3mf, docx/xlsx/pptx
    zipfile.js     minimal zip reader (stored / deflate / zstd)
    mesh.js        STL/OBJ/3MF geometry stats
    text.js        STEP, DXF, G-code, KiCad, plain text
    image.js       EXIF + nativeImage thumbnails
src/main/
  health.js        library consistency check (catalogue vs disk), read-only
  export.js        project -> zip (files, _versions, thumbs, project.json, README)
  sheets.js        HTML -> PDF via hidden BrowserWindow (Letter/Ledger) for add-ins
src/renderer/
  index.html       layout: sidebar / main / inspector; CSP
  app.js           all UI state and rendering (vanilla JS module); pages: home, project, tools, settings, search
  addins/index.js  ADD-IN REGISTRY: list of { id, name, icon, blurb, render(container, ctx) }
  addins/sheets.js Drawing Sheets add-in (title + divider pages)
  viewer.js        three.js viewer + thumbnail render, pdf.js, video frame
  styles.css       JDot-style dark theme (+ light)
  vendor/          generated by scripts/vendor.js; committed
scripts/           vendor.js, make-icon.js, smoke.js
```

Data flow for a new file: `addFile` copies it in, inserts item+version, runs
`extract()`; if the handler returns `pending` ("mesh" | "pdf" | "video") the
renderer's `runPending()` picks it up, renders, and calls `completePending`.

Library disk layout is documented at the top of `library.js`.

## The extension points

**Add-ins (Tools page):** create `src/renderer/addins/<name>.js` exporting
`{ id, name, icon, blurb, render(container, ctx) }` and list it in
`addins/index.js`. `ctx` gives `api`, the open `project` (or null), all
`projects`, `toast`, and `refresh`. Anything needing Node goes through a new
IPC handler in main.js + preload.js, like `sheets:save`.

**File formats:**

Add a format in `src/main/extract/index.js`: put the extension in `KINDS` and, if
it has data or a thumbnail to pull, add a handler to `HANDLERS` returning
`{ image?, meta?, text?, pending? }`. Put the parsing itself in the module that
matches its container (OLE, zip, text). Nothing else needs to change; the
inspector renders whatever `meta` contains (nested objects become collapsible).

- **Folder paths use `/` in the catalogue and `path.sep` on disk.** `category`
  and `folders.path` are always `/`-separated (`Library.normPath`); `folder`
  and `relpath` are OS paths (`diskPath`). `migrateCategories()` fixes rows
  written before 0.3.0. Moves are one `fs.rename` plus a prefix rewrite of
  every `relpath` under it (`rewriteRelpaths`), so never update `category`
  directly: go through `moveProject` / `moveFolder`.

- **Inputs without `type="text"` render unstyled** (white boxes). The base CSS
  targets `input:not([type])` too now, but keep `type="text"` on new inputs.
- **The bottom layout** (`.app[data-layout=bottom]`) needs the inspector body
  split into `.insp-a` / `.insp-b`; a CSS `columns` trick clipped the second
  half. Both columns scroll independently.

- **Fusion 360 `.f3d` is a zip with Zstandard (method 93) entries.** jszip
  throws "compression \x5D unknown". `zipfile.js` handles it via Node's
  `zlib.zstdDecompressSync`, which exists in Electron's Node but needs Node
  22.15+ outside Electron. Thumbnail is `*/Previews/small.png`.
- **Bambu Studio `.3mf` keeps geometry in `3D/Objects/*.model`,** not
  `3D/3dmodel.model` (that one only holds build items). Aggregate every
  `.model` entry or you get 0 vertices.
- **Inline `<script type="importmap">` is blocked by the page CSP,** so bare
  `three` imports can't be mapped. `scripts/vendor.js` rewrites `from 'three'`
  to a relative path when copying addons. Re-run `npm run vendor` after
  bumping three.
- **`lib://` fetches from the `file://` page are CORS-blocked** unless the
  scheme is registered with `corsEnabled: true` AND the handler adds
  `Access-Control-Allow-Origin: *`. `<img>`/`<video>` tags worked without it,
  which hides the problem until three.js/pdf.js use fetch/XHR.
- **`npm install` may not download the Electron binary** because allow-scripts
  blocks install scripts; `node node_modules/electron/install.js` fetches it.
- **Renderer preview failures clear `pending`.** A failed mesh/pdf/video job
  records a "Preview error" in meta and won't retry; use the ↻ button or
  Settings → Re-read all files.
- **OLE property-set stream names start with `\x05`** (`\x05SummaryInformation`).
  Match on the name with that prefix stripped. The user-defined property names
  dictionary must be decoded with the section's code page, which can appear
  after the dictionary in the property list, so read the code page first.
- **SolidWorks parsing is unverified.** No real `.sldprt` existed on this
  machine when written; the 3DEXPERIENCE cache files under
  `AppData\Local\DassaultSystemes` are encrypted, not OLE.

## Roadmap (unbuilt)

- Real 3D for native CAD (needs SolidWorks/eDrawings/Inventor installed, or
  STEP via occt-import-js WASM).
- Fusion 360 cloud hub listing/download via the Fusion API.
- HEIC/TIFF thumbnails (heic-convert is pure JS).
- Smart folders / saved searches; bill-of-materials view across projects.
- Import wizard that maps an existing NAS folder tree onto categories/projects.

## Release

Bump `version` in `package.json`, update `CHANGELOG.md` in the same commit,
tag `vX.Y.Z`, push the tag. CI builds the NSIS installer and uploads it with
`latest.yml` and the `.blockmap` (required by the silent updater).
